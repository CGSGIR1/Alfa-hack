# Передача в GitHub

Версия для сдачи отправляется в ветку `integrate-full-system` приватного
репозитория `CGSGIR1/Alfa-hack`. Итоговая папка `github/` в комплекте сдачи —
отдельная рабочая копия с историей. Исходная папка разработчика сохранена.
Публикация этой ветки не меняет `main`: объединение выполняется отдельно,
после просмотра изменений и проверки совместимости с командными коммитами.

## Перенос готовой версии в main

Ветка `integrate-full-system` подготовлена как полная замена файлов `main`
готовым комплектом. История `main` включена в историю ветки; исходный код,
интерфейс и данные берутся из проверенной версии 1.1.0. Переписывание истории
и `git push --force` не требуются.

На GitHub откройте Pull Request с **base: main**, **compare: integrate-full-system**.
Проверьте состав изменений и успешное завершение GitHub Actions на Windows,
Linux и в Docker, затем используйте обычное объединение **Create a merge commit**.
До объединения `main` остаётся без изменений. Предыдущее состояние сохраняется
в истории и при необходимости восстанавливается отдельным коммитом отката.

## Git Bash

Перейдите в папку `github` итогового комплекта. Затем:

```sh
git remote -v
git branch --show-current
git status --short
git diff --cached --stat
```

Ожидаемые значения: `origin` → `https://github.com/CGSGIR1/Alfa-hack.git`,
ветка → `integrate-full-system`. Удаление старых файлов в списке изменений
означает замену прежней поставки подготовленным составом, а не изменение main.

Если автор Git ещё не задан, задайте свои данные только в этой копии:

```sh
git config user.name "Ваше имя"
git config user.email "Ваш email GitHub"
```

После просмотра изменений:

```sh
git add --all
git diff --cached --stat
git commit -m "Подготовлена итоговая версия новостной аналитики"
git push -u origin integrate-full-system
```

Если удалённая ветка обновилась и Git отклоняет push, не используйте `--force`.
Сначала выполните `git fetch origin` и проверьте различия с командой.
После push создаётся Pull Request в main; публикация ветки сама main не меняет.

## Что входит в Git

Код, интерфейс и его медиа, параметры без секретов, шаблон `.env.example`,
закрытая папка `private-data/` с CSV и подготовленными JSON корпуса, тесты, CI и инструкции. Копия `design/reference.html`
нужна проверке исходных стилей. Исследовательские превью и экспортные архивы исключены.

В Git не должны попасть:

- `.env` и действующие ключи;
- `.venv`, веса Gemma и оригинальные PDF;
- `runtime/`, БД, кеши, рабочие отчёты и логи;
- Docker-архив `.tar` и архивы поставки.

Проверка поставки без секретов и весов:

```sh
python tools/verify_submission.py .
```

Репозиторий должен оставаться **приватным**: `private-data/` содержит CSV
организаторов и производные материалы. Перед push убедитесь, что `origin`
указывает на закрытый репозиторий. Его историю тоже нельзя публиковать:
старые коммиты содержат предыдущие материалы.

Docker публикуется отдельно новым пакетом `alfa-hack-public`, без `private-data/`.
Подготовленные данные уже лежат рядом с Compose; получателю не нужна ручная
перекладка или авторизация в GHCR после публикации очищенного образа.
