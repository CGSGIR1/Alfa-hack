## Компоненты

| Этап | Реализация | Результат |
| --- | --- | --- |
| Запуск | `app.py`, `src/integration/cli.py`, `src/integration/web.py` | CLI, пользовательский сайт `/`, служебный `/manage`, фоновые циклы |
| Сырые новости | `src/parser/parser.py`, `src/parser/retention.py` | RSS, извлечённый текст, блоки, отдельная SQLite парсера |
| Разметка новости | `src/news_prep/pipeline.py`, `src/integration/preparation_retry.py` | Фрагменты, цитаты и два представления новости; состояния ошибок и повторов |
| Новая компания | `src/integration/onboarding.py`, `profiles.py`, `src/company_profile/` | Факты из CSV, уточнённые аспекты, валидированный JSON профиля |
| Импорт | `company-news-analytics/news_analytics/importing.py` | Версии документов, фрагменты и записи входов для эмбеддингов |
| Векторы | `company-news-analytics/news_analytics/embedding.py` | Локальные Gemma-векторы пяти ролей, хеши, ревизии и переиспользование |
| Поиск | `company-news-analytics/news_analytics/retrieval.py`, `src/integration/admission.py` | Компания → новость; две аналитические ветви; пересечение и пороги |
| События и квоты | `src/integration/events.py`, `financial_events.py`, `topic_quota.py` | Проверяемые идентичности финансовых фактов и лимит темы процентных ставок |
| Очередь | `company-news-analytics/news_analytics/workflow.py`, `src/integration/service.py` | Версии сравнений, подготовленная партия, завершение, ограниченные повторы |
| Агенты | `src/report/deep.py`, `package.py`, `assess.py`, `verify.py` | Два мнения, арбитр, разбор влияния, синтез, критик и проверки |
| Доказательства | `src/integration/report_context.py`, `adapter.py` | Сохранённые цитаты, страницы, происхождение аналитики и результат очереди |
| Лента | `src/integration/site.py`, `web_static/site-adapter.js` | Проекция сохранённых отчётов, SSE, стабильные карточки и обновления |

`src.pipeline` и `src.embeddings/stub.py` содержат исторические компоненты.
Рабочий векторный поиск не использует символьные векторы или старую БД pipeline.
При этом чистые функции упаковки фактов компании, рыночных показателей и
вспомогательные функции агентов переиспользуются там, где это явно вызвано.

## Основные таблицы SQLite

| Таблицы | Назначение |
| --- | --- |
| `companies`, `company_queries` | Профили и активные поисковые аспекты компаний |
| `news`, `article_chunks` | Исходные снимки новостей и их смысловые фрагменты |
| `analytics`, `analytics_pages`, `analytics_visuals` | Метаданные аналитики, страницы и сведения о графиках/таблицах |
| `analytics_chunks`, `analytics_mechanisms`, `analytics_mechanism_sources` | Источники, причинные механизмы и проверяемые связи между ними |
| `embedding_inputs` | Тексты и векторы ролей `company_query`, `news_context`, `news_mechanism`, `analytics_source`, `analytics_mechanism` |
| `company_news_checks` | Результаты сравнений с ревизиями профиля, новости и настроек, состояние очереди |
| `company_reports`, `company_report_batches` | Снимок подбора, результаты LLM, статусы партий и сведения о повторах |
| `news_preparation_jobs` | Память первичной разметки и её состояний |

Исходная новость и готовый отчёт — разные сущности. Исходные статьи ограничены
сроком хранения, а готовые отчёты и сохранённые доказательства остаются в архиве.
Удаление файлов из `runtime/reports/` само по себе не сбрасывает память обработанных
пар в SQLite. Квота «Процентные ставки» читается из завершённых снимков отчётов,
не требует новой таблицы и сохраняется после удаления исходной статьи.

## Векторы и поиск: инварианты

- Размерность — 768, `float32`, нормализация; для запроса и документа используются
  разные промпты и методы Gemma. Превышение 2048 токенов не скрывается обрезкой.
- Компания ищет по `news_context`. Запрос `news_mechanism` ищет одновременно по
  `analytics_mechanism` и `analytics_source`. Подмена его вектором контекста
  компании на аналитическом этапе не выполняется.
- Пересечение проверяется по ссылкам на все исходные фрагменты механизма для
  одного и того же фрагмента новости. Сходства тем недостаточно.
- Векторы — кандидаты для проверки LLM. Они не устанавливают причинность или
  фактическую экспозицию компании и не заменяют исходные цитаты.
- Подтверждающие факты компании формируются кодом из CSV. Гипотезы поисковых
  аспектов и условия применимости отделены от фактов.

## Работа процессов и интерфейса

Парсер и получение готовых карточек не требуют ручного обновления страницы.
Генерация для выбранной компании и добавление профиля сериализуются в рабочей
очереди: текущий платный запрос не прерывается новым выбором. Работа модели
и запись защищены блокировками; сравнения и статусы сохраняются после перезапуска.
Сайт читает уже сохранённые результаты, а не вызывает LLM при раскрытии карточки.
SSE сообщает изменение ревизии ленты; клиент загружает обновлённые данные и
показывает новые карточки последовательно.

Обычная поставка рассчитана на один локальный экземпляр. Выбранная компания —
состояние сервера, а не изолированная пользовательская сессия каждого браузера.
Встроенной многопользовательской авторизации нет. В Docker CSV подключаются с хоста в
`/app/private-data/csv`, остальные входные JSON — в `/app/private-data/`. Gemma — в `/models/embeddinggemma-300m`, состояние — в `/app/runtime`.
API-ключ передаётся при запуске, а не включается в исходники или слои образа.

Организаторы используют свой ключ LLM, указанный в `.env`. Наличие ключа у человека
не передаёт его приложению автоматически: приложение получает его при запуске
контейнера. В стандартном Compose адрес API, модели и пути уже заданы шаблоном.
Новая сборка образа предназначена для публичного скачивания без авторизации GHCR.
Материалы остаются в приватном репозитории и подключаются Compose только для чтения.
Авторизация GitHub нужна для скачивания репозитория; ключ LLM нужен для работы API.
