# Новости в отчёте только при наличии подобранной аналитики

24 октября 2026 года. Правило применяется к формированию входа для итоговой LLM и новой выдачи компании.

До выбора количества новостей проверяется наличие хотя бы одной аналитической связи в пересечении двух веток существующего поиска. Пороги, число кандидатов и сами векторы не менялись. Единственный кандидат из одной ветки не открывает доступ к итоговому отчёту.

Новость без связи остаётся в основной базе и очереди, но не отправляется итоговым агентам и не занимает место подходящей новости. Компания–новость повторно по векторам не сравнивается: используется сохранённый результат. При следующих проходах наличие аналитики проверяется снова, поэтому добавление аналитического материала может сделать новость доступной для отчёта. Текущие ограничения срока давности сохраняются.

Если подходящих новостей с аналитикой нет, возвращается `idle` и итоговая LLM не вызывается. Это не отключает предшествующую разметку новых публикаций моделью.

Сборщик пакета также исключает новости, которым фактически не досталось аналитической связи после ограничения объёма пакета. Это действует и при выгрузке пакета из старого сохранённого отчёта. Исходные сохранённые файлы отчётов не перезаписываются.

Старая подготовленная партия, содержащая неподдержанную новость, отменяется при возобновлении; очередь строится заново по текущему правилу. Это относится также к команде `finish`. Новости, исключённые из пакета, не помечаются обработанными итоговой LLM. Лента не показывает записи, отсутствующие в отфильтрованном пакете.

На 16 сохранённых отчётах проверены 39 включений новостей: у 14 отсутствовала связь из пересечения. При формировании пакетов они исключены, осталось 25 включений. Это подсчёт включений в отчёты, не уникальных публикаций.

Новые тесты: отсутствие платного вызова итоговой LLM при пустой аналитике; повторное рассмотрение после появления аналитики без повторного расчёта сходства компании; замена неподдержанной новости в ограниченной выдаче; отклонение одноветочного совпадения; безопасное завершение старой партии; скрытие таких новостей в пакете и ленте. Проверки выполняются на временных базах с подставными ответами, без обращений к API.
