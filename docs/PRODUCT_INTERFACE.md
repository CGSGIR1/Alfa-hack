# Пользовательский сайт и служебный интерфейс

Основной сайт запускается через `start_interface.cmd`. Его оформление основано
на `design/reference.html` — переданном `index (6).html`. Исходный CSS сохранён
побайтово. Кнопки «Ещё», профиль и настройки не открывают внутреннее управление.
На странице нет кнопок импорта, запуска LLM, статуса сборщика и служебных ссылок.
Обработка и доставка новых карточек продолжают работать в фоне.

Служебный интерфейс открывается отдельным файлом `start_management.cmd`:

```powershell
.\.venv\Scripts\python.exe -B tools\launch_interface.py --view manage
```

Скрипт открывает `/manage`. Если сервер уже работает с основной базой,
повторный экземпляр не создаётся. Если нет — запускается тот же сервер
сразу с открытием служебной страницы. Для работы основного сайта держать
служебную страницу открытой не требуется. В ней доступны импорт, ручной
поиск, отчёты, история и переключатель автоматической обработки.

## Оформление карточек

Основные вкладки соответствуют образцу: «Кратко», «Подробно», «Мнение банка»,
«Что не установлено», «Рекомендации». При внешней аналитике подпись вкладки
указывает на аналитиков, чтобы не приписывать её Альфа-Банку. Условность
выводов сохранена. Блоки отчёта используют исходные nbt-blk, списки tl,
подписи типов утверждений tl-tag и красные маркеры #EF3124 из исходного CSS.
Дополнительные блоки, раньше помещённые во вложенные раскрывающиеся разделы,
убраны из пользовательской карточки вместе с содержимым: исходные абзацы,
цитаты, подготовленные тезисы и контекст, разбор механизмов, ограничения
источников и история публикаций. Основной итоговый текст LLM, оценки,
условность и рекомендации сохранены. Вкладка мнений содержит только итоговые
оценки LLM. Полные материалы остаются в данных и служебном интерфейсе.
Служебные оценки арбитра не подмешиваются к тексту отчёта.

Все карточки показаны в одной ленте по времени доставки: новости и отдельные
сценарии компании используют общие фильтры, счётчик непрочитанного и очередь
поступления по одной карточке. У сценария остаётся небольшая пометка «Контекст
компании», отдельного раздела и заголовка нет. Рыночные показатели остаются
в виджете на главной; отдельных блоков под лентой нет. Исходные типы данных
и проверка применимости в LLM не меняются.

Подпись прототипа удалена. Плашка «Новое» использует исходные стили index,
без глянца и дополнительных переопределений. Заголовки не выделяются,
основной текст по-прежнему можно копировать. Красное свечение использует
исходные анимации index: glow (7 секунд) и glow2 (9 секунд), без случайных
траекторий. Оно отключается при системной настройке уменьшения движения.

Фильтр «За всё время» сохраняет ранее согласованное бессрочное накопление
карточек. Даты получения и выбор реальной компании остаются рабочими
вместо демонстрационных данных образца.

## Курсы валют

Виджет «Конвертация» получает справочные курсы наличной валюты Альфа-Банка
с автоматическим обновлением раз в минуту. Подробности — в `CURRENCY_WIDGET.md`.

## Иконка

Локальный `src/integration/web_static/favicon.ico` получен с официального
`https://alfabank.ru/favicon.ico`, указанного пользователем сайта Альфа-Банка.
Файл ICO, 4286 байт, основной размер 32×32. URL и SHA-256 сохранены в
`design/favicon-manifest.json`. Иконка выдаётся локально на `/favicon.ico`;
при открытии сайта браузер не обращается за ней к внешнему ресурсу.

## Проверка

99 интеграционных тестов, клиентские проверки обновлений и тесты отображения
отчётов прошли. В браузере проверены отсутствие служебных диалогов/ссылок,
раскрытие карточки, красный цвет маркеров rgb(239,49,36), нулевые margin/padding
цитат и отдельный служебный интерфейс. Иконка проверена как ICO.
Проверки использовали сохранённые данные без LLM и без изменения основной БД.

Код до изменений сохранён в
`runtime/changes/product-interface-20261025-115321/before.zip`.


## Анимированные карточки на главной

На месте «Платёжных связей» размещены две карточки из тестового HTML.
Сохранены поднятое видео, размытое продолжение цветов по краям и анимированная рамка.
Первая ссылка открывает страницу переводов Альфа-Банка, вторая — PDF Consumer Research.
Обе открываются в новой вкладке; ссылки доступны с клавиатуры.
Видео загружаются как локальные MP4 с поддержкой HTTP Range, не встроены в HTML.
Фон синхронизирован с кадрами видео; вне главной страницы и в фоновой вкладке
воспроизведение приостанавливается. Учитывается уменьшение движения.
Кнопок паузы, просмотра и разворачивания нет. Бейджи «Демо» и «Альфа-Банк»
у виджетов удалены; обязательная отдельная пометка исходной аналитики сохранена.
Тестовый HTML в `design/animation-card-demo/` остаётся самостоятельным.

## Обновлённая главная и движение

Одобренный вариант `design/home-layout-demo/` перенесён в основной интерфейс.
Вверху находятся счета, «Дела в работе» и карточка банковской карты.
Карусель новостей расположена широким прямоугольником над конвертацией и двумя
видео; «Активные заявки» имеют высоту по содержимому. Карта, значок и подпись
реагируют на указатель с разной глубиной; весь блок ведёт на
`https://alfabank.sale/corporate/cards/`.

Переходы используют затухание и появление, дискретное колесо мыши — короткое
сглаживание. Уменьшение движения отключает эффекты. Новая навигация отменяет
старую. Сдвиг ленты при поступлении материалов компенсируется мгновенно.
По умолчанию тема тёмная; переключатель сохраняет выбор пользователя.

Поведение включено в существующий `app.js`, стили — в `integration.css`,
поэтому новые маршруты сервера и перезапуск не требуются. Адаптер рабочей
ленты, SSE, поиск, БД, векторизация и вызовы LLM переносом не менялись.
Самостоятельный макет пересобирается `python design/home-layout-demo/build.py`.
Флаг `--review` создаёт версию с вымышленными материалами и профилем для коллег.

## Добавление компании из CSV

Внизу списка компаний есть кнопка «Добавить компанию». В окне принимаются
`U_9250` и `9250`; номер — значение `SYNTHETIC_U`, а не порядковый номер строки.
Готовый профиль из БД или входных JSON используется повторно. Если его нет,
собираются факты из CSV и уточняются аспекты через LLM (либо берётся её кеш).
LLM не заполняет отсутствующие факты догадками. Используется тот же контракт
`company-profile-2.0`, что у исходных десяти компаний.

Нужны три файла: `df_Uid_data_hack.csv`, `df_Uid_payment_hack.csv`,
`df_Fid_Uid_link_hack.csv`. Папка задаётся через `DATA_DIR` в `.env`, затем
`company_profiles.csv_directory` в `config.json`; по умолчанию это `data/`.
CSV локальны и не добавляются в Git. В контейнер их нужно подключить отдельным
томом, например `./data:/app/data:ro`; Windows-путь внутри контейнера не работает.

Операция выполняется в фоне в общей очереди. Добавление не ждёт всю партию:
фоновый цикл отдаёт очередь после завершения
текущего вызова и сохранения его результата, затем возобновляется. Повторное
нажатие для той же компании возвращает ту же выполняющуюся задачу. JSON сначала
проверяется, затем сохраняется в `runtime/uploads/companies/` и импортируется
транзакционно. Векторизуются только поисковые запросы этой компании. После
успеха сайт выбирает её и обычная автоматическая обработка начинает подбор.
Подготовка профиля сама не создаёт отчёт и не включает выключенную автоматику.

При ошибке CSV/LLM компания не добавляется. При ошибке модели после сохранения
профиля повтор продолжает векторизацию без повторной генерации профиля.
При перезагрузке вкладки сайт продолжает наблюдать уже запущенную задачу.
Задачи хранятся в памяти сервера; после его перезапуска повторите добавление,
сохранённый JSON и кеш LLM будут использованы повторно.

В отличие от статических правок главной, для нового маршрута `/api/add-company`
нужен однократный перезапуск сервера. Старый сервер показывает понятное сообщение
о необходимости перезапуска, не запускает лишних API-запросов.
