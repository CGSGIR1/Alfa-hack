# Отделение итогового отчёта от служебной проверки — 25.10.2026

Публичные карточки и представление полного отчёта используют финальные поля
автора: brief, why_you_see_this, why_it_matters, risks, opportunities, bank_view.
Технические reason оценщиков и арбитра не являются описанием влияния на бизнес.
Они остаются в сохранённом JSON и трассировке и не выводятся вместо итогового текста.

Вкладка аналитики показывает источники, на которые ссылаются утверждения
итогового текста. Учитываются ссылки на механизм, исходный фрагмент и документ.
Это распространяется на дополнительные источники, найденные инструментами агента.
Само попадание кандидата в пересечение поиска не является основанием для его
показа как аналитического объяснения. Отброшенные кандидаты не добавляются к
итоговому тексту автоматически.

Независимый контекст компании отображается только по разделу independent_risks
итогового автора и явно отделяется от объяснения конкретной новости. Служебные
company_context.statement не подменяют подготовленный для читателя текст.

Снимки отчётов и источников не переписываются. Обработка LLM, поиск, пороги,
кандидатные пулы, бессрочная лента и очистка исходных новостей не изменены.
Фильтрация реализована также в JavaScript: старый работающий сервер с прежней
проекцией данных поддерживается после обновления страницы. Серверная проекция
также исправлена и будет загружена при следующем запуске.

Проверка: 94 интеграционных теста; JavaScript-проверки обеих версий интерфейса,
совместимости со старой проекцией и сохранения источников. В браузере проверен
реальный сохранённый отчёт U_9250 по просрочке инфраструктурных подрядчиков.
Было 4 материала-кандидата и 2 служебные оценки; в итоговом представлении —
2 цитируемых материала, без opinion_1/opinion_2 и путей фактов из разбирательства.
Тексты, цитаты и пометки материалов организаторов сохранены.

## Накопление отдельного контекста компании

Раздел «Важно независимо от новостей» собирается из всей истории завершённых
отчётов компании. Пустой раздел в новом отчёте не удаляет ранее показанные
выводы. Для одного механизма показывается последняя сохранённая версия со
стабильным идентификатором карточки; дата, источники и условия относятся к
этой версии. Это отдельный аналитический сценарий, а не ещё одна статья.

API помечает полный архив как independent_risks_scope=history. Старые запущенные
серверы, возвращающие лишь последний раздел, также поддерживаются: клиент
сохраняет уже показанный контекст до смены компании. После перезапуска сервер
может восстановить весь раздел из сохранённых отчётов. Между компаниями
контекст не переносится. Полностью пустой архив нового API остаётся
авторитетным, например после явной очистки истории.

Воспроизведение на U_9250: обе новости сохранены; вывод о лизинге из первого
отчёта восстанавливается после второго отчёта без independent_risks. Проверка
всего интеграционного набора: 95 тестов, плюс клиентские проверки обновления,
сохранения карточки и изоляции компаний. Новых LLM-вызовов нет.

Изменение не выполняет новых вызовов LLM и не меняет данные основной БД.
