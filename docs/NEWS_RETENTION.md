# Автоматическое хранение новостей

В `config.json`, раздел `pipeline`:

```json
"news_retention_days": 10,
"cleanup_interval_seconds": 3600
```

Возраст считается по дате публикации относительно календарной даты Москвы.
Удаляются записи строго старше 10 дней. Например, на 25.10.2026 удаляются
публикации до 15.10.2026; сама дата 15.10 ещё сохраняется. Окно поиска отдельно
настроено на 7 дней и этой правкой не меняется.

Очистка выполняется при запуске сайта и инициализации данных, затем во время
фоновых циклов не чаще раза в час и при смене календарной даты. Перед ручным
поиском, подготовкой, векторизацией и завершением отчёта также проверяется срок
очередной очистки. Без запущенного сервера или worker фоновой работы нет.

Удаляются старые новости, их фрагменты, записи сравнений компания/новость и
неиспользуемые новостные векторы. Общие векторы, на которые ссылаются оставшиеся
материалы, сохраняются. Аналитика, компании и их векторы не затрагиваются.
Очищаются также база парсера, её CSV и доступные по идентификаторам устаревшие
записи журнала подготовки. Неизвестная/неверная дата парсера не служит основанием
для удаления.

Готовые отчёты и их снимки источников сохраняются бессрочно и остаются в ленте.
По умолчанию выбран период «За всё время». Фильтры 1/5/7 дней считают возраст
по дате получения отчёта в Москве. Дата самой статьи отдельно показана в источниках.
Идентификатор группировки сохраняется при завершении отчёта, чтобы после
удаления исходной новости карточка не превратилась в новую непрочитанную.
Исторический вывод относится к дате его подготовки; эта дата отмечена у сводки.

Если незавершённая
партия содержит просроченную новость, она отменяется; свежие новости из неё
возвращаются в очередь. Исторический отчёт не требует сохранения строки `news`.

Парсер пропускает устаревшие RSS-записи до скачивания статьи. Импорт при запуске,
CLI и загрузка через сайт пропускают старые JSON: удалённые новости не появляются
обратно после перезапуска. Оригинальные JSON и PDF на диске не удаляются.

Проверка без удаления:

```powershell
.\.venv\Scripts\python.exe app.py cleanup --dry-run
```

Немедленная очистка:

```powershell
.\.venv\Scripts\python.exe app.py cleanup
```

Результат последнего запуска: `runtime/news-retention.json`. Перед изменениями
создаются полные резервные копии SQLite в `runtime/backups` и
`runtime/parser/backups`. Для готовых отчётов и этих копий автоматический срок
хранения не установлен; данная операция их не удаляет. Освобождённые страницы SQLite повторно
используются: уменьшение числа записей не обязательно уменьшает размер файла.

`--as-of YYYY-MM-DD` предназначен для проверки границ на тестовой копии базы;
без него используется текущая дата. Очистка не вызывает LLM и не вычисляет
эмбеддинги.
