# Интеграционный протокол

Единый вход — `python app.py`, конфигурация — корневой `config.json`, секреты —
корневой `.env`. Флаг `--config PATH` или `--env-file PATH` ставится перед командой.
Для `.env` не используется выполнение кода; уже заданное окружение имеет приоритет.

## Подготовленные материалы

```sh
python app.py init
python app.py import --news path/to/news --companies path/to/companies --analytics path/to/analytics
python app.py embed
python app.py generate --company U_102920
```

Импорт принимает прежние схемы: company-profile-2.0, news-two-views-1.0,
analytics-contextual-mechanisms-2.0. По одному документу на JSON. Плохие новости
пропускаются с перечислением причин; ошибки компаний и аналитики требуют исправления.
До следующего шага проверяйте код завершения и `rejected_count`.

Из CSV организаторов можно непосредственно создать и импортировать компанию:

```sh
python app.py company-from-csv --company U_102920 --csv-dir path/to/csv
```

В папке должны быть df_Uid_data_hack.csv, df_Uid_payment_hack.csv,
df_Fid_Uid_link_hack.csv. Флаг `--refine` использует LLM для уточнения аспектов.
Группы `group_...` поддерживаются отдельно; список участников сохраняется.
Прежняя БД `src.pipeline` и его StubStore в этом пути не используются.

## Сырые новости и фоновый цикл

`parse` запускает исходный парсер с `--data-dir runtime/parser`, поэтому его
рабочие файлы не попадают в каталог исходников и не меняют старый news.db.
`prepare-news` выбирает полные статьи, одну на событие, из окна новостей. На вход
LLM поступают реальные абзацы B001… с метаданными; нормализатор проверяет цитаты,
покрытие и два текста для эмбеддинга. Перед импортом проверяется лимит токенов
Gemma; обрезание запрещено.

Журнал news_preparation_jobs находится в основной БД. Идентичность обработки:
ID статьи + хеш исходного запроса + версия промпта. Готовое не размечается повторно.
Три содержательные ошибки требуют ручного `--retry-failed`; сбой API остаётся
повторяемым и не исчерпывает лимит качества статьи. Ошибка одной статьи не
мешает другим. После общей ошибки API цикл не тратит запросы на остальные статьи.

`tick` собирает → размечает → векторизует → сравнивает → генерирует отчёты.
У `tick` можно явно указать `--company ID`; без этого используется только сохранённая
в интерфейсе выбранная компания. Если выбора ещё нет, обновляются только новости.
Кнопка «Обновить новости» всегда только пополняет общую базу; автоматический цикл
добавляет отчёт для выбранной компании. Выбор сохраняется через POST
`/api/select-company` с JSON `{"company_id":"U_102920"}`. В локальном прототипе
это один общий текущий профиль. Флаги `--no-parse`, `--no-prepare`, `--search-only` позволяют
проверять этапы отдельно. CLI возвращает ненулевой код при ошибках отчётов,
не удаляя уже успешно обработанные материалы. Worker продолжает последующие циклы.

## Соединение поиска и LLM

Поиск выдаёт **report-generation-input-1.1**. В src/report/package.py добавлена
поддержка этой версии, исходных абзацев и точной пометки организаторской аналитики.
Версия 1.0 оставлена для чтения старых пакетов. Сходство не передаётся писателю
как вероятность; ни одно пересечение не означает доказанную причинность.

src/report выполняет оценку → проверку → при необходимости дозапрос → написание →
проверку кодом и критиком → одну доработку. Если остались структурные/проверяемые
ошибки, результат не подтверждается. Достоверность экономических выводов проверки
кода не доказывают, поэтому остаются условия и ссылки на источники.

src/integration/adapter.py превращает ответ писателя в **company-analysis-report-1.1**:
сохраняет request_id, company_id, as_of; включает каждую новость, даже отклонённую;
передаёт оценки связей; цитаты восстанавливает из проверенных символьных диапазонов.
Самостоятельно важный механизм хранится в company_context, а не объявляется
объяснением неподходящей новости. Полный читабельный ответ — в `narrative`.

Только после validate_result и complete_batch партия считается завершённой.
Сбой оставляет её prepared; `finish --company ID --run-id ID` продолжает тот же
пакет. Если результат уже сохранён на диск, повторное подтверждение не вызывает
LLM заново. Остальные подходящие новости остаются в очереди, включая новости,
не вошедшие в текущий лимит. При `idle` старый отчёт не публикуется повторно.

## Интерфейс

GET /api/state, /api/history, /api/jobs/ID, /api/batch — состояние и результаты.
POST /api/import — готовые JSON; /api/search — только поиск; /api/generate —
полный отчёт; /api/tick — обновление ленты; /api/complete — ручной приём результата.
Для POST обязательны Content-Type: application/json и
X-Requested-With: news-analytics-ui. Одна фоновая задача сериализует операции UI;
общая файловая блокировка защищает от одновременного изменения через CLI.
Ключи и содержание .env в API состояния не возвращаются.

Это локальный прототип: перед публичным размещением нужны аутентификация,
HTTPS и разграничение доступа. Compose по умолчанию публикует только localhost.
