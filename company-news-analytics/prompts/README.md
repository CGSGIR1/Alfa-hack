# Промпты и контракты внешних LLM

1. `analytics_json.md` — полная инструкция подготовки аналитического PDF.
2. `news_json.md` — полная инструкция подготовки очищенной новости.
3. `report_generation.md` — инструкция итоговой оценки найденных связей.
4. `../docs/LLM_REPORT_INPUT.md` — формат пакета на вход итоговой LLM.

Скопируйте именно текст между разделителями в системную роль. Исходник и
метаданные — отдельное пользовательское сообщение/вложение. Локальный путь
`path/to/file.pdf` сам по себе не передаёт PDF другой LLM: приложение должно
прикрепить файл, изображения или фактическую расшифровку через поддерживаемый API.
Если выбранная LLM не читает изображения, нужны OCR и проверенные описания графиков.
Провайдер и модель этими файлами не задаются; используйте разрешённую кейсом LLM.

Схемы совместимы с текущими импортерами:
- аналитика — `analytics-contextual-mechanisms-2.0`;
- новости — `news-two-views-1.0`;
- пакет итоговой LLM — `report-generation-input-1.1` (отдельный выход после поиска).

## Почему аналитика сначала является черновиком

LLM формирует содержательные поля и доказательства, но оставляет null в
служебных полях: SHA-256, embedding_text, source_text/source_pages механизма,
обратные mechanism_ids. Программа строит тексты эмбеддинга по фиксированному
шаблону, вычисляет хеши и связи. Это сохраняет выбранную схему и освобождает LLM
от ненадёжного расчёта хешей и многократного копирования одних и тех же строк.

```powershell
python -m news_analytics.llm_io prepare-analytics --input incoming/analytics-draft.json --pdf "data/sources/analytics/actual-report.pdf" --metadata incoming/analytics-input.json --output incoming/analytics-ready.json
```

`analytics-input.json` — исходный пакет с `document_metadata` (см. пример).
`--metadata` сверяет ID, название, дату/месяц, издателя и количество страниц,
не позволяя LLM поменять их. `--pdf` обязателен: хеш вычисляется по реальному файлу.
Уже заполненное вычисляемое поле с неверным значением отклоняется, а не исправляется молча.
Скрипт не делает OCR, не считывает графики и не доказывает достоверность текста.
Он проверяет структуру и связи; page_count должен быть взят приложением из реального PDF.

```powershell
python -m news_analytics.llm_io prepare-news --input incoming/news-draft.json --metadata incoming/news-input.json --output incoming/news-ready.json
```

Для новости обработчик применяет ту же нормализацию двух представлений, что
импортёр. При переданном исходном пакете сверяет метаданные и неизменность
source_blocks, проверяет цитаты и их привязку. Полнота и смысловая точность
всё равно требуют контроля — одна структурная валидация их не гарантирует.

Загрузите **ready**, а не draft, через интерфейс или:

```powershell
python run.py import --analytics incoming/analytics-ready.json --news incoming/news-ready.json
python run.py embed
python run.py compare --company U_102920 --as-of 2026-10-22
```

Для обновления существующих документов добавьте `--update-existing`; перед
изменениями импортёр создаст резервную копию. Фрагменты аналитики с изменённым
исходным текстом требуют новых ID. Error-ответы LLM не являются входом импортера.
Неправильный JSON не следует «чинить» удалением цитат, оговорок или целых страниц.

## Пакет для итоговой LLM

```powershell
python -m news_analytics.llm_io report-input --input reports/ЗАПУСК/company_U_102920.json --output incoming/report-input.json
```

По умолчанию передаётся компактная часть пересечения: до двух механизмов на
новость и до пяти уникальных механизмов на пакет компании. `--include-candidates`
разрешает дополнения механизменной ветви в пределах того же лимита, если у них
есть отличающийся канал и новые исходные доказательства. Пересечение имеет приоритет. Надёжный порог
автоматических дополнений пока не установлен. Не выдавайте дополнения за пересечение.

В папке `examples/llm` лежат небольшие **синтетические** входы/черновики и полный
пример пакета итоговой LLM. Это демонстрация формата, не реальные источники и не
оценка качества. Примеры готовых текстов эмбеддинга получаются после подготовки.

Внешние API этим кодом не вызываются. Перед реальным вызовом проверьте бюджет
контекста/выхода выбранной модели. Для большого документа нужен отдельный
процесс обработки порций с сохранением межстраничного контекста и последующей
сборкой; данный обработчик сам не объединяет частичные PDF-разметки. Не просите
LLM уместить документ ценой потери данных или выдачи обрезанного JSON.

Поиск через CLI и сайт автоматически сохраняет `llm-input-ID.json` рядом с
поисковым отчётом. В интерфейсе есть кнопка «Вход для LLM». Полный JSON поиска
сохраняет всех кандидатов; компактные HTML/экран и пакет ограничивают выдачу.
Настройки поиска (10 на ветвь, те же вектора и пересечение) не заменяются лимитом
пакета. Дополнительная проверка финансовых тем может добавить новость сверх основной выдачи; финансовых событий суммарно не более одного.

prepare-news теперь требует исходные source_blocks. Для каждой цитаты проверяются
точное вхождение, минимум 40 символов и 6 слов. Это не семантическая экспертиза.
Старые JSON без блоков импортируются для совместимости; в пакете их недостаточная
трассируемость явно отмечается. Исходные блоки нельзя восстанавливать из пересказа.
