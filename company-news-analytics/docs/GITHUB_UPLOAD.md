# Отправка подготовленной папки в GitHub

Архив поставки — способ передать папку проекта. Распакуйте его и отправляйте
содержимое папки репозитория, а не ZIP одним файлом. Модель находится отдельно.

1. Создайте пустой репозиторий в нужном аккаунте/организации GitHub.
2. Откройте терминал в корне распакованного проекта.
3. Проверьте файлы перед коммитом:

```sh
python tools/verify_release.py
git init
git branch -M main
git add .
git status --short
```

`git status` должен показывать код, документацию, подготовленные JSON/PDF и тесты.
В нём не должно быть `.env`, весов модели, `.venv`, SQLite-баз и личных отчётов.
Это обеспечивают `.gitignore` и проверка манифеста поставки. Созданные позже
локальные файлы всё равно проверяйте перед отправкой.

4. Замените URL в команде ниже на адрес вашего репозитория:

```sh
git commit -m "Add company news analytics module"
git remote add origin https://github.com/USER/REPOSITORY.git
git push -u origin main
```

Git запросит обычную настроенную авторизацию GitHub. Пароли и токены не добавляйте
в файлы проекта. Никакие ключи для запуска GitHub Actions в этой поставке не нужны.

После отправки вкладка Actions запустит тесты на Windows/Linux и сборку Docker.
Этот workflow не публикует Docker-образ и не загружает модель. Если общая система
должна получать готовый образ из GHCR или Docker Hub, публикация настраивается
отдельно с выбранным именем репозитория и реестра.

Поставка сама по себе ничего в GitHub не отправляет: коммит, remote и push остаются
под контролем владельца репозитория.
