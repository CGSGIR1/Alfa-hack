# Протокол подключения к общей системе

Команды выполняются из корня проекта интерпретатором окружения Python 3.12.
Все примеры ниже используют `python`; на Windows без активации замените его на
`& .\.venv\Scripts\python.exe`, на Linux — на `.venv/bin/python`.
Модель задаётся через `model_path`, `--model` или `EMBEDDING_MODEL_PATH`.

## 1. Первоначальная загрузка

```sh
python run.py init
python run.py import --companies data/input/companies --analytics data/input/analytics
python run.py embed
```

По умолчанию база находится в `data/news-analytics.db`. Для отдельной базы
передавайте один и тот же `--db PATH` всем командам. Полные PDF не считываются
импортёром автоматически: он принимает готовые JSON, включая описания графиков.

## 2. Каждая партия новостей

Сохраните по одному документу на файл в отдельную папку задания. Разметка должна
соответствовать `news-two-views-1.0`: исходные блоки/цитаты, фрагменты, тезис,
контекст, механизм с условиями и поисковый вопрос. Формат: `INPUT_FORMATS.md`;
промпт: `../prompts/news_json.md`.

```sh
python run.py import --news data/incoming/JOB_ID/news --update-existing
python run.py embed
python run.py compare --company U_102920 --output reports/JOB_ID
```

После каждого этапа проверяйте код завершения. Ненулевой код означает ошибку;
зависимые этапы не запускайте. У импорта stdout содержит `Import: {...}`:
проверяйте `rejected_count`/`rejected_news`, даже если код равен нулю.
Некорректные новости пропускаются, остальные продолжают загружаться.
Ошибки компании/аналитики по-прежнему отклоняют их пакет.

Команда `import --news` выбирает только новости. `embed` вычисляет все недостающие
активные векторы базы, готовые совместимые векторы берёт из кеша. Объединённый
`run` импортирует все три типа из настроенных папок; для потока используйте
отдельные команды выше. Сами числовые векторы во входные JSON добавлять не надо.

## 3. Ответ compare

Для одной компании возвращается JSON, например:

```json
{
  "status": "prepared",
  "company_id": "U_102920",
  "run_id": "GENERATED_RUN_ID",
  "output": "ABSOLUTE_RUN_DIRECTORY",
  "summary": {},
  "workflow": {
    "new_comparisons": 20,
    "queued_before_selection": 6,
    "selected_news": 3,
    "queued_after_selection": 3
  }
}
```

Здесь показаны ключи, а не полный фактический ответ. Статусы:

| Статус | Действие общей системы |
| --- | --- |
| `prepared` | Читать пакет из `output` и передавать итоговой LLM |
| `resumed` | Та же незавершённая партия; продолжить её, используя тот же request_id |
| `idle` | Нового пакета нет; не вызывать LLM и не публиковать старый latest повторно |

У `idle` нет `run_id`/`output`. `resumed` может указывать на папку прежнего запуска,
несмотря на новый `--output`. Читайте путь из ответа, а не вычисляйте его сами.
`latest.json` служит только указателем и при `idle` не обновляется.
Без `--company` возвращается `results`: отдельный результат для каждого профиля.

Пакет для итоговой LLM: `<output>/llm-input-U_102920.json`.
Другие файлы: `company_U_102920.json`, `company_U_102920.md`, `report.html`,
`comparisons.csv`, `run.json`. Для ID с нестандартными символами имя файла
безопасно преобразуется; смотрите `run.json`.

## 4. Вызов итоговой LLM и завершение

Внешняя система передаёт инструкцию `prompts/report_generation.md` и пакет
`report-generation-input-1.1`. Автоматического API-клиента LLM в модуле нет.

Сохраните ответ модели в отдельный JSON со схемой `company-analysis-report-1.1`.
В нём должны сохраниться исходные `request_id`, `company_id`, `as_of`. В `items`
нужен элемент для каждой новости, в том числе для отклонённых связей; иначе
новость считалась бы завершённой без результата. Истинность рассуждений модели
структурной проверкой не доказывается.

```sh
python run.py complete --company U_102920 --run-id RUN_ID --result data/incoming/JOB_ID/llm-result.json
python run.py history --company U_102920
```

Проверяются идентификаторы, охват новостей, ссылки оценок и цитаты. Ответ сохраняется
в базе и `llm-result-ID.json` рядом с пакетом. В локальном интерфейсе он появляется
в истории компании; в интерфейсе есть и загрузка ответа через файл.
Повтор `complete` с тем же ответом безопасен, с другим ответом отклоняется.

Общая система публикует отчёт на своём сайте и использует `request_id` как ключ
идемпотентности. `complete` сам не вызывает сторонний сайт. Не считайте простое
создание входного пакета подтверждением успешной работы LLM или публикации.

При сбое:

```sh
python run.py fail --company U_102920 --run-id RUN_ID --error "LLM timeout"
```

Партия остаётся `prepared`; сохраняются причина и счётчик попыток. Следующий
`compare` вернёт тот же пакет без нового сравнения. Если ответ LLM уже сохранён
внешней системой, повторите его передачу в `complete`, не вызывая модель заново.

## 5. Учёт проверок и очередь

Ключ проверки — компания/версия профиля + новость/версия содержания + версия
модели и параметров построения сравнения. Сохраняются и отрицательные результаты.
Одна новость независимо проверяется для разных компаний. Лимит выдачи не удаляет
подходящие новости из очереди; перед включением снова проверяется их актуальность.
Для компании допускается одна незавершённая партия одновременно.

При первом запуске журнал пуст: проверяется накопленный набор в окне дат.
Старые отчёты поиска не считаются подтверждением работы LLM. Изменение профиля,
содержания новости, модели или параметров построения сравнения требует новых
проверок. Смена количества новостей не пересчитывает оценки. Обновление аналитики
само по себе не переоткрывает завершённые новости; очередь получает аналитику при
подготовке очередного пакета.

Настройки сохраняются из `config.json`. Примеры:

```sh
python run.py compare --company U_102920 --top-news 5 --news-days 30
python run.py compare --company U_102920 --as-of 2026-10-23
python run.py status
```

Дата по умолчанию — текущая дата Москвы. Новости должны иметь возраст меньше
`news_days`; дата поступления не заменяет дату публикации. Финансовое покрытие
может добавить новость сверх `top_news`, при этом финансовых событий не больше
одного. Для строгого общего лимита отключите покрытие явно:
`--top-news N --financial-topic-coverage 0`.

## 6. Идемпотентность импорта и восстановление

- Неизменные документы пропускаются; изменённым нужен `--update-existing`.
- Один канонический URL соответствует одной новости. Новый ID подготовки известного
  URL связывается с её стабильным ID; тот же ID с другим URL отклоняется.
- Входной каталог сканируется рекурсивно: не кладите туда ответы LLM, служебные
  манифесты или JSON других типов. Используйте отдельные папки заданий.
- При прерывании `embed` повторите его. Завершённые пакеты сохранены в кеше.
- Сбой аналитики/записи отчёта не удаляет очередь. Назначение новостей партии
  фиксируется одной транзакцией со снимком отчёта. Основные файлы потерянного
  пакета восстанавливаются из SQLite при возобновлении.
- Новые исходные тексты аналитики требуют новых ID фрагментов; изменённый PDF —
  нового ID документа. Исходные цитаты не восстанавливаются по догадке.
- Выполняйте задания записи/векторизации последовательно. Подготовка/завершение
  партии защищены межпроцессным `*.workflow.lock`, но это не очередь всех импортов.
  Если блокировка занята, повторите команду после завершения текущего задания.
- В приложении вызывайте команды через `subprocess.run([...], check=True)` с
  аргументами списком, рабочей папкой проекта и захватом stdout/stderr. Для каждого
  задания сохраняйте run_id, request_id, статус и пути пакета/ответа.

Краткий контракт: JSON → import → embed → compare → LLM → complete → история.
