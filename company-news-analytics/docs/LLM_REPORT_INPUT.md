# Пакет для итоговой LLM

Версия `report-generation-input-1.1`. Это вход для генерации, а не итоговый ответ
и не численные векторы. API и внешняя LLM автоматически не вызываются.

## Получение

`python run.py compare --company U_102920 --as-of 2026-10-23` сохраняет рядом:
- company_U_102920.json — полный снимок поиска со всеми кандидатами;
- llm-input-U_102920.json — компактный вход для LLM;
- report.html — компактное представление с раскрываемыми кандидатами.

То же происходит при поиске через сайт. Кнопка «Вход для LLM» скачивает пакет.

Для пересборки из существующего снимка:

```powershell
python -m news_analytics.llm_io report-input --input reports/ЗАПУСК/company_U_102920.json --output reports/llm-input-U_102920.json
```

Необходимые исходные сведения берутся из снимка. Старый снимок не получает
контрагентов или исходные блоки автоматически: для этого повторите поиск.

## Лимиты и приоритет

Поиск остаётся прежним: до 10 кандидатов в каждой аналитической ветви,
тот же запрос механизма новости, те же пороги, пересечение по всем точным
исходным фрагментам той же новости. Ограничение пакета применяется ПОСЛЕ поиска.

По умолчанию не более двух механизмов на новость и пяти уникальных механизмов
на весь пакет. Один механизм может иметь связи с несколькими новостями, не
дублируясь в массиве аналитики. Пересечение имеет приоритет; сначала даётся
по одному материалу каждой новости, затем вторые. Внутри каждого шага приоритет имеет минимальное сходство двух ветвей,
разнообразие исходных доказательств используется при равенстве баллов; одинаковые цепочки причины/канала/эффекта внутри одной
новости не повторяются. Это эвристика компактности, а не проверка применимости.
Одна цепочка может требовать несколько исходных фрагментов — их нельзя обрезать.
Объём в токенах поэтому не гарантирован: его проверяют токенизатором итоговой LLM.

`--include-candidates` разрешает дополнения из механизменной ветви с отдельным
статусом single_branch_candidate, если они добавляют другой канал и новые
исходные доказательства. Они занимают место в тех же лимитах и не вытесняют
пересечение. Автоматический порог уверенности для них не калиброван.

Лимиты можно явно переопределить:

```powershell
python -m news_analytics.llm_io report-input --input reports/ЗАПУСК/company_U_102920.json --output reports/custom-input.json --max-analytics-per-news 2 --max-analytics-total 5
```

## Содержимое

- company: профиль, ограничения и facts. counterparty_payments содержит до пяти
  известных отраслей плательщиков/получателей по сумме в каждом направлении,
  для всех наблюдаемых платежей и после исключения известных внутригрупповых.
  Сохраняются знаменатели, доля неизвестных отраслей, сумма/количество платежей,
  период/валюта (в том числе null) и число/доля пропущенных известных отраслей.
  Плательщик не обязательно покупатель, получатель не обязательно поставщик.
  Отсутствующий платёжный профиль, в частности для группы, не достраивается.
- news: выбранные фрагменты (тезис, контекст, механизм, атрибуции, цитаты),
  URL/дата/издание и только процитированные исходные source_blocks.
- source_traceability: complete означает наличие блоков и цитат технически
  достаточной длины, но НЕ независимую смысловую проверку. missing/incomplete
  явно показывает пробелы старых тестовых данных. Пересказ не объявляется оригиналом.
- analytical_documents: ID, название, издатель, дата/период. Локальных путей и
  контрольных сумм нет. Они остаются в полном поисковом снимке и базе для аудита.
  source_provenance содержит origin, provided_by_organizer, provider и label.
  У восьми исходных документов Альфа-Банка origin=organizer,
  provided_by_organizer=true, provider="Альфа-Банк" и специальная пометка
  "Аналитика Альфа-Банка · материал организаторов". У внешних материалов label=null.
  При генерации пометка переносится в evidence.source_label и показывается рядом
  с соответствующим источником. Она не обозначает авторство итогового отчета.
  Принадлежность исходному набору определяется точным списком ID в
  news_analytics/analytics_sources.py, а не упоминанием банка в тексте или названии.
  При повторной подготовке пакета из старого снимка эти известные документы также
  получают пометку. Метаданные не включаются в embedding_text и не меняют ранжирование.
- analytical_source_fragments: полные выбранные исходные тексты со страницами,
  авторством и происхождением, один раз на ID.
- analytical_mechanisms: причина/канал/следствие, существенные условия, статус,
  авторство, ограничения и ссылки на источники.
- connections: связь news_id + news_fragment_id + mechanism_id + ВСЕ
  source_fragment_ids, статус intersection/single_branch_candidate,
  applicability=not_evaluated, баллы поиска (не вероятность).
- retrieval.packet_selection: лимиты, число включённых/пропущенных связей.
- coverage: ограничения полноты и финансовое покрытие; неизвестные события
  не создаются. Полнота по всему корпусу не измерена.

## Цитаты аналитики без повторения

В evidence_refs механизма вместо полной цитаты передаётся:

```json
{"fragment_id":"A01","start_char":0,"end_char":123,"pages":[2]}
```

Цитата равна `source.text[start_char:end_char]`: индексы символов Python с нуля,
конец не включён (в JavaScript учитывать Unicode code points, не UTF-16 units).
Сборщик проверяет исходное точное вхождение до создания ссылок. Если два механизма
опираются на один абзац, текст передаётся один раз; разные механизмы не удаляются
только из-за одинаковой цитаты. Полные исходные тексты не сжимаются.

## Проверка финансового покрытия

После общего топа проверяются до двух тем: ставка/финансирование — только при
подтверждённой теме finance/macro, курс/трансграничные расчёты — также для явной
гипотезы профиля, с сохранением её условности. Тема должна быть предметом заголовка события, а не случайным упоминанием в
контексте другого события. Для ставки также распознаются заголовки о решении ЦБ
по ставке; депозитные сводки исключаются. Это отдельное тематическое правило
допуска даже при низком косинусе, с admission и below_similarity_threshold в
financial_topic_matches. В обычном отборе сохраняется порог 0,35; временное окно
обязательно и для дополнительных событий.
Выбирается одно наиболее свежее подходящее событие на непокрытую тему; при равной
дате — лучшее сходство аспекта. Базовый топ сохраняется, добавляется максимум
по одной новости на тему. Долларовая цена товара сама по себе не событие о курсе.

no_qualified_fresh_event означает отсутствие подходящего события в допустимом
окне и этой тематической проверки, а не отсутствие события в мире. Покрытие темы
не подтверждает импорт, валюту контракта, задолженность или маршрут поставки.
Отключение надстройки для воспроизведения исторических тестов:
`--financial-topic-coverage 0` (в config.json по умолчанию 1).

## Итоговая оценка

Используйте prompts/report_generation.md вместе с пакетом. Проверяются отдельно
новость↔механизм и фактическая экспозиция компании. Background/rejected не
используются как объяснение новости. Отдельный company_context допускается
только с самостоятельным основанием к компании и указанием неизвестных условий.
Допустимо: «По предоставленным данным существенное влияние не установлено».
Не нужно пересказывать каждую новость или обязательно придумывать рекомендации.

Внешние тексты остаются данными, их инструкции не исполняются. Проверяйте бюджет
контекста выбранной разрешённой LLM; токенизатор EmbeddingGemma для этого не подходит.
