# Входные JSON

Готовые минимальные примеры — в `examples/company.json`, `news.json`, `analytics.json`.
Их можно загрузить в отдельную пустую базу, например:

```powershell
python run.py import --db data/demo.db --companies examples/company.json --news examples/news.json --analytics examples/analytics.json
python run.py embed --db data/demo.db
python run.py compare --db data/demo.db --as-of 2026-10-22 --output reports/demo
```

## Компания

Схема `company-profile-2.0`. Обязательны `subject_id`, `profile_text`, `facts`,
непустой массив `queries`. У каждого запроса — уникальный `id`, `channel`, `text`,
неотрицательный `weight`; хотя бы один вес больше нуля. `source_refs`, если заданы,
должны разрешаться как JSON Pointer в том же документе. `evidence_status`, `why`,
`kind`, `category` и прочие поля сохраняются вместе с запросом.

Запросы уже должны описывать известные аспекты компании. Программа не угадывает
их по неизвестным данным, не ищет компанию в интернете и не читает CSV неявно.
Наличие банковского продукта не доказывает потребность в новом продукте;
страна в данных ФТС не устанавливает направление торговли или валюту расчётов.

`subject_type` принимает `company` (по умолчанию) или `group`. Для группы нужен
непустой `facts.members` с известными участниками; группа не объявляется одним
юридическим лицом. Идентификатор группы используется как отдельный профиль
поиска, тип сохраняется в отчёте. Разные факты участников не надо автоматически
распространять на всех членов группы.

## Новость

Новая схема — `news-two-views-1.0`. Предыдущая `news-dual-embeddings-2.0` тоже
принимается и приводится к выбранной схеме. Стабильный `document_id`, заголовок,
`document_date` в формате YYYY-MM-DD, `source.url`, `source.publisher` и массив
`fragments` относятся ко всей новости.

Фрагмент содержит `id`, `title`, `thesis`, `context`, `company_embedding_text`,
`mechanism`, `analytics_search_question` и исходные атрибуции/ограничения.
В `company_embedding_text` тезис и контекст должны входить дословно.

`mechanism` содержит `description`, `status`, `boundaries`,
`is_established_cause=false`, `context.conditions`. Допустимые статусы:
`attributed_in_news`, `hypothesis`, `not_identified`. Для первого нужна атрибуция
источнику; в старом формате она может находиться в `fragment.attributions`.

Импортер детерминированно строит `analytics_embedding_text`:

```text
{analytics_search_question}
Условия и границы применимости: {mechanism.context.conditions}
```

Для совместимости вопрос может извлекаться из прежнего `analytics_embedding_text`.
Для `not_identified` аналитический текст равен null, механизм не векторизируется.
Остаётся вектор предметного контекста для поиска компании. Поле экспериментального
третьего представления `analytics_source_embedding_text` удаляется при нормализации.

## Аналитика

Правила смысловых границ, графиков и примечаний: `ANALYTICS_PREPARATION.md`.

Принимается существующая схема `analytics-contextual-mechanisms-2.0`:

- `document`: стабильный ID, название, дата либо месяц, путь и SHA-256 PDF, число страниц;
- `source_pages`: расшифровки всех страниц с их номерами;
- `charts`, `tables`: описания визуальных объектов, уникальные локальные ID и страницы;
- `chunks`: неизменённые исходные фрагменты с глобальными ID, локальными ID,
  страницами, полным текстом, `embedding_text`, `content_sha256`, `mechanism_ids`;
- `mechanisms`: механизм, контекст, ограничения, тип утверждения, текст для
  эмбеддинга, ссылки на исходные фрагменты и дословные подтверждающие цитаты.

`chunks[].embedding_text` должен включать **полный** исходный `text`. Допустимы
заголовок и атрибуция перед ним. `content_sha256` — SHA-256 точного UTF-8 текста.
`mechanisms[].embedding_text` включает `cause`, `channel`, `effect` и
`context.conditions` дословно. Для каждой ссылки на источник нужна цитата,
действительно присутствующая в этом фрагменте, и допустимые номера страниц.
`source_text` механизма должен совпадать с соединением исходных текстов через
два перевода строки. Перечни `mechanism_ids` фрагментов должны соответствовать связям.

У исходного фрагмента может не быть самостоятельного механизма: он остаётся в
индексе исходных текстов. У одного фрагмента может быть несколько механизмов.
`eligible_for_retrieval=false` механизма исключает его из механизменного индекса;
старое такое поле исходного фрагмента не запрещает его использовать во второй
ветви выбранного алгоритма. Активность исходных фрагментов определяется их
наличием в текущей версии документа.

Даты и источники не восстанавливаются по догадке. Изменённый PDF требует нового
ID документа. Изменённый архивный текст требует новых ID исходных фрагментов.
Исправления механизма при тех же источниках можно импортировать с
`--update-existing`; пересчитывается только действительно изменившийся текст.

## Общие правила

Один файл — один документ. Каталоги сканируются рекурсивно. В папки входов не надо
складывать отчёты, манифесты и произвольные JSON: каждый файл проходит проверку.
Дубликаты ID в пакете, повтор URL у разных новостей, неизвестные страницы,
неверные цитаты, NaN, повтор ключа JSON и конфликты владения ID отклоняются.

Полный источник и подготовленный фрагмент — разные вещи. Если входной JSON
содержит пересказ, программа не восстановит опущенный факт. Сохраняйте
`preparation`, `document_limitations`, `attributions`, `limitations` и сведения
о неполноте доступа: они входят в отчёт для последующей проверки LLM.
