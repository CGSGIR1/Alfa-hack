# Структура SQLite

Авторитетная схема: `news_analytics/schema.sql`. Новая рабочая база —
`data/news-analytics.db`. Старую базу не надо передавать новой версии как рабочую:
при несовместимой схеме программа откажется её изменять.

| Таблица | Назначение |
|---|---|
| companies | Профиль, факты, полный входной JSON компании, хеш импорта |
| company_queries | Отдельные аспекты бизнеса, веса, основания, активность, ссылка на вектор |
| news | Метаданные и исходный подготовленный JSON новости |
| article_chunks | Тезис, контекст, две ссылки на входы векторов, атрибуция и ограничения |
| analytics | Метаданные документа и полный подготовленный JSON |
| analytics_pages | Расшифровки страниц |
| analytics_visuals | Описания графиков/таблиц с привязкой к странице |
| analytics_chunks | Исходные аналитические фрагменты и ссылка на вектор всего фрагмента |
| analytics_mechanisms | Выделенные механизмы с контекстом и ссылка на вектор |
| analytics_mechanism_sources | Точные связи механизма с фрагментами и подтверждающие цитаты |
| embedding_inputs | Тексты и кеш векторов пяти разрешённых ролей |
| comparison_runs | Параметры, модель, дата и итоги каждого запуска |
| company_reports | Полный снимок отчёта компании на дату запуска |
| company_news_checks | Проверенные версии пар компания/новость, оценки, очередь и назначение партии |
| company_report_batches | Партии prepared/completed/cancelled, ошибки и сохранённые ответы LLM |

`active_embedding_inputs` — представление только входов, на которые ссылаются
активные объекты. В базе могут оставаться неиспользуемые старые входы векторов;
они не сравниваются и не вычисляются повторно без активной ссылки.

Пять ролей: `company_query`, `news_context`, `news_mechanism`, `analytics_source`,
`analytics_mechanism`. Роли `news_source` в выбранном алгоритме нет. Вектор хранится
как 768 нормализованных float32 little-endian, 3072 байта. Сохраняются модель,
отпечаток весов/настроек/версий библиотек, способ кодирования, префикс, хеш входа,
число токенов и время вычисления. Изменение входного текста в существующей записи
запрещено: новый текст получает другую запись. Перед сравнением проверяются и
метаданные, и реальные байты вектора.

Тексты фрагментов сохраняются полностью как TEXT. Входной JSON — снимок для
проверки происхождения; рабочие связи и поисковые поля выделены в таблицы. PDF —
в `data/sources/analytics`, а его SHA-256 и путь сохраняются в метаданных.
Исторический отчёт содержит копии использованных текстов и остаётся понятным
после обновления текущих профилей и разметки.

Сводки связей и платежей компании сохраняются в её исходном JSON. Новая версия
не пытается заново загрузить сырые CSV и не создаёт отдельные таблицы для физических
лиц: для согласованного поискового механизма достаточно подготовленного профиля.

Примеры SQL:

```sql
SELECT role, COUNT(*) AS inputs, SUM(embedding IS NOT NULL) AS vectors
FROM active_embedding_inputs GROUP BY role;

SELECT n.title, c.local_id, c.thesis, c.context,
       ec.text AS company_search_text, em.text AS analytics_search_text
FROM article_chunks c JOIN news n ON n.id=c.news_id
JOIN embedding_inputs ec ON ec.id=c.context_input_id
LEFT JOIN embedding_inputs em ON em.id=c.mechanism_input_id
WHERE c.is_active=1;

SELECT r.id, r.as_of, r.summary_json FROM comparison_runs r ORDER BY created_at DESC;
```
