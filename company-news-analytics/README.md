# Компания → новости → аналитика

Модуль принимает подготовленные JSON компаний, новостей и аналитики, сохраняет их
в SQLite, вычисляет локальные эмбеддинги и формирует пакет для итоговой LLM.
Проверки ведутся отдельно для каждой компании: неизменные пары компания/новость
повторно не сравниваются, подходящие материалы сверх лимита остаются в очереди.

В репозитории есть CLI, локальный веб-интерфейс, Dockerfile, Docker Compose,
промпты, тесты и подготовленный набор: **11 профилей, 614 новостей, 22 аналитических
документа с PDF**. Модель Gemma, виртуальное окружение, рабочая база и история
пользователя в поставку не входят. База и векторы создаются при первом запуске.

## Граница модуля

```text
Внешняя система: парсинг → очистка → LLM-разметка JSON
                                      ↓
Наш модуль:         import → embed → compare
                                      ↓
Внешняя система:              итоговая LLM
                                      ↓
Наш модуль:                complete → история компании
```

Этот код не вызывает внешние LLM и не содержит ключей API. Парсер сайтов, OCR и
подготовка исходной разметки выполняются до импорта. Инструкции для внешних моделей
находятся в `prompts/`; список разрешённых LLM определяет общий проект/кейс.

## Быстрый запуск: Docker Compose

Нужны Docker с Compose v2 и отдельно скачанная полная папка
`google/embeddinggemma-300m`. Веса автоматически не скачиваются.

1. Скопируйте `.env.example` в `.env`.
2. В `.env` задайте `MODEL_HOST_PATH`: путь к полной папке модели на вашем компьютере.
   Можно использовать путь вне репозитория. На Windows используйте прямые слеши.
3. Из корня репозитория выполните:

```sh
docker compose up --build
```

Откройте <http://127.0.0.1:8765/>. Если порт занят, измените `APP_PORT` в `.env`.
Модель подключается только для чтения; база и отчёты сохраняются в `data/` и
`reports/` на хосте. Остановка: `docker compose down`; данные после неё остаются.

Для включённого исторического набора выберите дату **23.10.2026** или нажмите
«Дата материалов». На текущую дату старые новости могут не пройти окно 30 дней.
Первый поиск вычисляет все недостающие векторы и занимает больше времени, чем
повторные запуски. Обновляйте состояние через интерфейс, не запускайте параллельно
несколько импортов/векторизаций одной базы.

При повторном поиске незавершённая партия возвращается с тем же `request_id`.
Скачайте «Вход для LLM», получите ответ внешней модели и загрузите его в блоке
«Готовый отчёт». После сохранения можно готовить следующую партию.

## Запуск без Docker

Поддерживаемая среда — Python **3.12**, Windows или Linux x86-64, CPU. Создайте
окружение в корне проекта и установите зафиксированные зависимости.

Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:EMBEDDING_MODEL_PATH = "ПУТЬ/К/embeddinggemma-300m"
.\.venv\Scripts\python.exe start_ui.py
```

Linux:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
export EMBEDDING_MODEL_PATH=/path/to/embeddinggemma-300m
.venv/bin/python start_ui.py --no-browser
```

Можно вместо переменной окружения задать `model_path` в `config.json`.
По умолчанию это `models/embeddinggemma-300m`. Файл `.env` читает Docker Compose;
обычный запуск Python автоматически его не загружает. Интернет нужен для установки
библиотек; кодирование текста использует локальную модель в офлайн-режиме.

## Командный цикл интеграции

Ниже `python` означает интерпретатор подготовленного окружения. В PowerShell
можно вместо него писать `& .\.venv\Scripts\python.exe`.

Первоначальная загрузка включённых компаний и аналитики:

```sh
python run.py init
python run.py import --companies data/input/companies --analytics data/input/analytics
python run.py embed
```

Каждая новая партия готовых JSON новостей:

```sh
python run.py import --news data/incoming --update-existing
python run.py embed
python run.py compare --company U_102920
```

Для проверки включённого набора:

```sh
python run.py import --news data/input/news
python run.py embed
python run.py compare --company U_102920 --as-of 2026-10-23
```

`compare` возвращает JSON: `prepared` — новый пакет, `resumed` — ранее
подготовленный пакет, `idle` — новых подходящих материалов нет. При наличии
пакета читайте `output` и `run_id` из ответа команды. Файл для модели:
`<output>/llm-input-U_102920.json`. Полный поиск: `company_U_102920.json`;
просмотр: `report.html`. Пакет — вход для LLM, а не её итоговый бизнес-отчёт.

Завершение после ответа LLM:

```sh
python run.py complete --company U_102920 --run-id RUN_ID --result data/incoming/llm-result.json
python run.py history --company U_102920
```

Ответ LLM не кладите в папку, которую импортируете как новости. Отдельные
подпапки заданий удобнее общей папки `data/incoming` при смешанных типах файлов.

Эквивалентные команды контейнерного CLI:

```sh
docker compose --profile batch run --rm analytics import --news /app/data/input/news
docker compose --profile batch run --rm analytics embed
docker compose --profile batch run --rm analytics compare --company U_102920 --as-of 2026-10-23
docker compose --profile batch run --rm analytics complete --company U_102920 --run-id RUN_ID --result /app/data/incoming/llm-result.json
```

Полный протокол, ошибки, очередь и восстановление: [интеграция](docs/CLI_INTEGRATION.md).

## Выбранный поиск

- Компания: несколько векторов запросов по известным аспектам бизнеса.
- Новостной фрагмент: предметный контекст для компании и механизм с существенными
  условиями для аналитики. Механизм новости — поисковая гипотеза, не доказанная причина.
- Аналитика: отдельные векторы механизма с условиями и полного исходного фрагмента.
- Один запрос механизма новости ищется в двух аналитических индексах. По 10
  кандидатов на ветвь; пересечение требует точных исходных фрагментов того же
  механизма и того же фрагмента новости.

Текущие пороги: компания/новость 0,35, аналитика 0,375. Основная выдача — 3 новости,
до 2 механизмов на новость и до 5 уникальных механизмов в пакете. Финансовое
покрытие может добавить новость сверх основной тройки; финансовых событий в партии
суммарно не более одного. Настройки находятся в `config.json`.

Косинусное сходство не является вероятностью влияния. Итоговая LLM проверяет
условия, период, отрасль и известные факты о компании, может отклонить все связи.
Аналитические материалы организаторов имеют отдельную пометку Альфа-Банка.

## Проверки

Быстрые проверки не требуют Gemma или PyTorch:

```sh
python -m pip install -r requirements-test.txt
python -m unittest discover -s tests -p "test_*.py" -v
python tools/validate_inputs.py
python tools/verify_release.py
```

Проверка пяти реальных векторов, кеша и отказа от обрезания текста, после полной
установки зависимостей и подключения модели:

```sh
python -m tests.model_smoke --model /path/to/embeddinggemma-300m
```

Самодостаточная историческая регрессия с подключённой моделью и полными зависимостями,
без рабочей базы и без нового вычисления векторов:

```sh
python -m tests.regression --model /path/to/embeddinggemma-300m
```

Регрессия использует сохранённые векторы конкретной версии модели и библиотек;
несовпадающая версия отклоняется. Маленький исторический тест проверяет
воспроизводимость, а не качество на всех будущих новостях. GitHub Actions запускает
быстрые проверки на Windows/Linux и отдельно собирает контейнер без модели.
Фактически выполненные проверки этой поставки: [VALIDATION.md](docs/VALIDATION.md).
